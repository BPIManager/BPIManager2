# 「全曲」ページのスコア可視化に潜在能力推定を適用する（issue #386）

- **ステータス**: 検討中（issue #386 の受け入れ基準「データ量・カバレッジの調査結果」「実現可能なら本提案書」に対応）
- **前提**: 新方式BPI(V2)の決定記録 [0005](../decisions/0005-new-bpi-distribution-model.md)〜[0008](../decisions/0008-new-bpi-gamma-confidence-weighting.md)、ALS実装は `@bpim/bpidef`(`src/v2/als.ts`)・`BPIM2-AutomatedDefinitionCalculator`
- **重要**: 本提案が扱うのは☆11/12の本番BPI(V2)とは**別物の、全曲共通の新指標**である。決定記録0005§2で確定した「BPI100=歴代全一(WR)はBPIの定義的公理」という制約は、その公理を負っている**BPIそのもの**に対するものであり、BPIと名乗らない新指標には適用されない（詳細は後述）。

## 背景 / 動機

issue #386参照。現行の「全曲（☆10以下含む）」ページはEXスコアを「理論値に対するパーセンテージ」でのみ表示しており、譜面ごとの難易度・識別力の違いを反映しない。BPI(V2)と同様のALS（2母数潜在能力モデル）を☆10以下にも拡張できないか調査した。

## 調査1: データカバレッジ（受け入れ基準1）

`BPIM2-AutomatedDefinitionCalculator`が保持する最新クロール（`savedata/series_20260908_031839`、33バージョン分・6,000人）を実際に集計した。

### 母集団の偏り

クロール対象はアリーナ**A帯のみ**（`arena_class[0] === "a"`）。段位分布は次の通りで、**皆伝(3,580)・中伝(1,398)・十段(534)** が大半を占め、八段未満はほぼ皆無:

| 段位 | 人数 |
|---|---|
| 皆伝 | 3,580 |
| 中伝 | 1,398 |
| 十段 | 534 |
| 八段 | 277 |
| 九段 | 72 |
| その他(未設定含む) | 139 |

→ ☆11/12（現行BPIの対象）には妥当な母集団だが、☆1〜9にとっては**天井付近に偏った母集団**であり、母集団のスキル分散という観点では理想的ではない。

### レベル別のプレイ数（譜面あたり）

「一番プレイされている譜面」ではなく「プレイ数が概ね中央値の譜面」を各レベルから1つ抽出し、スコアレート分布を見た（母集団はA帯のみ）:

| レベル | 譜面 | n | 平均% | SD | p10 | p90 |
|---|---|---|---|---|---|---|
| 1 | ポラリスノウタ[B] | 29 | 92.0 | 20.7 | 93.0 | 99.7 |
| 4 | And-RoiD[N] | 28 | 96.3 | 2.3 | 94.4 | 98.1 |

→ 事前の懸念（低レベルは全員ほぼ満点で分散が無い）ほど極端ではなく、A帯母集団でも譜面によっては一定のスコア分散が残る。ただし**n=27〜41という極小サンプル**での分散推定自体が不安定であり、この結果を「低レベルでも推定可能」の根拠にするのは早計。

### 結論（調査1）

- 譜面メタデータ（notes・難易度）は`BPIM2-AutomatedDefinitionCalculator`の`constants/textage_*_meta.json`で全レベルカバー済み
- プレイヤーの生スコアは**全レベル分がクロール済み**（想定通り）だが、**低レベル譜面は譜面あたりのサンプル数が極端に少なく**（中央値15〜20人）、かつ**母集団がA帯（皆伝〜十段中心）に偏っている**ため、ALSでの位置・識別力推定は☆11/12ほど安定しないと見込まれる
- 実運用では、bpim2自身の全ユーザースコアデータ（クロールより遥かに大規模、決定記録0005§7でBPI(V2)母集団もクロール単独からbpim2データとのハイブリッドへ拡大した前例がある）を統合しないと、低レベル帯のサンプル数不足は解消されない可能性が高い

## 調査2: WRアンカー方式の妥当性（ユーザー提起、issue #386に関連）

検討中に「z100（BPI=100の基準点）を各曲の実際のWRでアンカーする現行方式ではなく、全曲共通の定数でアンカーしてはどうか」という案が出た。これは**issue #302 案A（決定記録0005§2で不採用）と同一の案**であり、まず経緯を確認する必要がある。

### 決定記録0005の既存結論（再掲）

> 「BPI100=歴代全一」という原典の前提を崩すべきではないという判断が確定した…案A（`z100`の全曲共通化）は最初から取り得ない

この不採用は**統計的な理由ではなく、「BPIとは何か」という製品定義上の理由**による。したがって☆11/12の本番BPI(V2)に対して同じ案を再度採用することは、この決定記録を覆す相応の理由が無い限り妥当ではない。

### ただし本提案（#386）は事情が異なる

#386で検討している指標は、そもそも「BPI」と呼ばれておらず、「BPI100=WR」という公理を最初から負っていない（#386の対応範囲外にも明記: 「☆11/12のBPI(V2)自体の変更ではない」）。したがって、この新指標に限っては**z100の全曲共通化は設計上の選択肢になり得る**。

### 実データでの検証（本番songParams.jsonより）

本番の`songParams.json`（mu/sigma、5,113人フィット）に対し、`bpim2_songs.tsv`・`textage_meta.json`・手元クロールのWRマスタで突き合わせ可能だった79曲（主にn≥500の良サンプル曲、手元クロールのWRマスタが不完全なためこの件数に留まる）について、曲ごとの実WRアンカー`z100_song = (t(WR)-mu)/sigma`を計算した:

| 指標 | 値 |
|---|---|
| 全曲共通定数（`songParams.json`の`z100`） | 6.52 |
| 79曲の`z100_song`分布: 中央値 | 6.23 |
| 同random: p10 / p90 | 5.36 / 8.44 |
| 同: 標準偏差 | 1.14 |

`z0`〜`z100`のフルスケール幅が約6.71（`z100 - z0` ≒ 6.52 - (-0.19)）であるのに対し、曲間の`z100_song`のばらつき（SD 1.14、p10-p90で3.1）は**フルスケールの2〜4割に相当する無視できない量**。つまり、良サンプルの☆11/12曲においては「その曲の実際のWRが平均よりどれだけ極端か」という情報は、単曲BPIに実質的な影響を与える現役の情報であり、全曲共通化すると失われる。

（サンプル数79・手元クロールのWRマスタは本番DBと非同期のため参考値に留まる。プレイ数区分別のばらつき比較も試みたが、高n譜面に偏ったサンプル構成のため`n`とばらつきの関係について結論を出せる規模ではなかった）

### 見解

- ☆11/12の**本番BPI**に対しては、決定記録0005の結論を覆すデータは今回得られていない（むしろ実WRアンカーが持つ情報量を裏付ける結果になった）。全曲共通化を再提案するなら、この情報損失を上回るメリット（低レベル帯拡張等）を、その根拠込みで新しい決定記録として起票する必要がある
- 一方で、#386の**新指標**（☆1〜10を含む、BPIとは独立の可視化指標）については、低レベル帯のWRが「たった15〜20人中の1人の記録」でしかない不安定な単一観測点になりうる（調査1参照）ため、実WRをアンカーに使う現行BPI方式をそのまま持ち込むのはリスクが高い。この新指標に限っては、**全曲共通アンカー（z0・z100とも共通定数）を採用する側に倒す**のが筋が良い

## 選択肢（#386の指標をどう作るか）

| 案 | 概要 | 評価 |
|---|---|---|
| A: 現行%表示を維持 | 何もしない | 譜面難易度差を反映しない現状の課題は残る |
| B: BPI(V2)と同じ実WRアンカー方式を☆1〜10にも適用 | `z100`を各譜面の実WRから算出 | 低レベル帯はWRサンプルが不安定（1人の記録に左右されやすい）。決定記録0005の懸念がより強い形で再燃する |
| C: 全曲共通アンカー（z0・z100とも共通定数）の新指標として設計 | BPIとは別の指標として、ALS推定のmu/sigmaのみを使い、WRに依存しない | 低レベル帯のサンプル不足・WR不安定性の影響を受けない。ただし個々の譜面の「実際のWRの極端さ」という情報は反映されない（BPIのgamma補正が担っている役割が無くなる） |

**暫定的な推奨: C案。** 理由: (1) 決定記録0005の制約は本指標には適用されない、(2) 調査1で示した通り低レベル帯はWRアンカーの前提（十分な母数からの信頼できる最大値）を満たさない、(3) ALSのmu/sigma自体はWRに依存せず観測スコア全体から推定されるため、C案でもモデルの根幹（曲の位置・識別力の相対比較）は維持される。

## 未解決の論点（要判断）

1. **母集団問題**: 現状のクロールはA帯（皆伝〜十段中心）に偏っている。低レベル帯を含む指標として成立させるには、bpim2自身の全ユーザースコア（決定記録0005§7のBPI(V2)母集団拡張と同様のハイブリッド化）を統合し、母集団のスキル分散を広げる必要がある可能性が高い。この場合、対象データが手元クロールからbpim2本番DBへ切り替わる
2. **サンプル数閾値**: ☆1〜6譜面の中央値15〜20人という値がALSの`minObservationsPerSong`をどの程度下回るか、実際にALSを走らせて`validSongIds`からの脱落率を確認する必要がある（今回は既存本番パラメータとの突合のみで、ゼロから低レベル帯のALSは実行していない）
3. **表示方針**: 現行%表示の完全な置き換えか、トグルによる併記か
4. **命名・独立性**: 「BPIではない指標」であることをUI上どう明確にするか（BPIとの混同はユーザーの誤解を招きうる）
