# 新方式BPIの変更点と恣意性の監査

`/new-bpi`で検証してきた分布ベース新方式（issue #299〜#311）が、原典・bpim2現行実装・当初のissue提案からどこをどう変えたかを、変更ごとに「なぜそう変えたか」「その決定に恣意性（根拠のない、あるいは結果に合わせて後付けで選んだ数値）がどの程度残っているか」を明記して棚卸しする。数式そのものの解説は[docs/bpi-math.md](bpi-math.md)、設計判断の記録は[decisions/0005](decisions/0005-new-bpi-distribution-model.md)・[decisions/0006](decisions/0006-new-bpi-latent-skill-shrinkage.md)を参照。本ドキュメントは「結局、原典からどれだけ・どこが恣意的に変わったか」を横断的に見るためのもの。

## 凡例（各変更点の分類）

- **統計的導出**: データ・モデルから数学的に一意に決まる、または既存の設計性質を維持するよう解析的に逆算した
- **仕様指示**: ユーザーからの明示的な要求に基づく（数式上の妥当性の問題ではなく仕様選択）
- **実測検証済み**: 複数案を比較し、実データでの挙動を確認した上で採用した設計判断
- **経験的校正（恣意性が残る）**: 具体的な数値を、目標とする結果に合わせて試行錯誤で決めた。原理的な導出ではないため、値を変えれば結果も変わる。本採用前に感度分析・再検討が望ましい

---

## 1. 単曲BPIの基礎量: `t = -ln(m-s)`

| 項目 | 内容 |
|---|---|
| 変更前 | 原典・現行: `PGF(x') = 0.5/(1-x')` を対数化した `ln(PGF)` |
| 変更後 | `t = -ln(m-s)` |
| 分類 | **統計的導出** |
| 根拠 | `t - ln(PGF(x')) = ln(2/m)`（曲固有の定数）であることを示した（[bpi-math.md §7.1](bpi-math.md#71-動機とモデル)）。ALS推定の`mu_j`がこの定数を自動的に吸収するため、実質的に同じ量を使っているに過ぎない |

## 2. 曲の形状パラメータ: `coef`(固定1.5→動的1値) → `mu_j, sigma_j`(分布から推定)

| 項目 | 内容 |
|---|---|
| 変更前 | 原典: 全曲共通で指数1.5固定。bpim2現行: 上位平均という1つの要約統計量から曲ごとに`coef`を逆算 |
| 変更後 | ALS（交互最小二乗）で曲ごとの位置`mu_j`・弁別力`sigma_j`を直接推定 |
| 分類 | **統計的導出**（推定手法自体）＋**経験的校正（一部残る）** |
| 根拠 | 要約統計量からの逆算ではなく分布そのものから推定するという方針転換は統計的に妥当。反復回数は当初`ITERATIONS=60`固定だったが、収束判定（aの反復間の最大変化量が母集団SDの0.01%を下回ったら打ち切り、固定回数は収束しない場合の安全装置に格下げ）に変更し、**統計的導出**に分類を変えた（実測: 19反復で収束、旧60回固定時とmu/sigmaの値はほぼ変化なし）。残るのは`minSongsPerPlayer=10`（ALS対象に含めるプレイヤーの最低プレイ曲数）で、これは依然として実務上の目安として選んだ整数のまま（後述） |

## 3. mu/sigmaの格納先: DBスキーマ → JSON

| 項目 | 内容 |
|---|---|
| 変更後 | `songs`/`songDef`にカラムを追加せず、`songParams.json`で保持 |
| 分類 | **仕様指示** |
| 根拠 | ユーザーからの明示指示（「ユーザーに変化を提示するための画面でmuやsigma、その他の新規指標が必要な場合はDBに追加するのではなく、jsonで楽曲ごとのデータを持ち使用する」）。数式上の妥当性とは無関係の、データ設計上の判断 |

## 4. ALS推定の母集団: アリーナ上位クロールのみ → クロール+bpim2自身のデータ

| 項目 | 内容 |
|---|---|
| 変更前（issue #300原案） | アリーナ上位クロールデータのみ（5,161人） |
| 変更後 | クロールデータに、クロール対象外のbpim2ユーザーを補完統合（5,942人） |
| 分類 | **実測検証済み**（母集団拡大で推定精度=R²が向上したことを確認） |
| 根拠 | 「同一プレイヤー×同一曲がクロールとbpim2の両方にある場合はクロール側を優先し、bpim2側では二重カウントしない」という統合ルールは、恣意的というよりは二重カウント防止として妥当な設計だが、他の統合方針（例: 新しい方の値を優先する、平均を取る等）もあり得たという意味では選択の余地があった点は留意 |

## 5. BPI=0のアンカー(`z0`): 曲ごとの実測 → 全曲共通の定数

| 項目 | 内容 |
|---|---|
| 変更前 | 原典・現行: 各曲の実際の皆伝平均を使う（曲ごとに異なる） |
| 変更後 | 全曲共通の定数（各曲の皆伝平均のz位置の**全曲中央値**、実測`z0≈-0.132`） |
| 分類 | **実測検証済み**＋**経験的校正（統計量の選び方）** |
| 根拠 | issue #299の実測で「皆伝平均アンカーの曲間ばらつきは元々小さい(0.53SD程度)」ことを確認しており、全曲共通化による歪みは小さい。ただし**「全曲中央値」という統計量自体の選択**（平均や最頻値ではなく中央値）は、外れ値に頑健という一般的な理由はあるが厳密な導出ではなく、実務上の妥当な選択という位置づけ |

## 6. BPI=100のアンカー(`z100`): 全曲共通化案 → 曲ごとの実WRを維持

| 項目 | 内容 |
|---|---|
| 変更前（issue #302原案） | `z100`も全曲共通の定数（`6.774`）にする提案。採用すれば「WR更新で他人のBPIが動く不安定性」も解消できるはずだった |
| 変更後 | **不採用**。「BPI100=歴代全一」という原典の定義を崩さないため、曲ごとの実際のWRから都度計算する方式を維持 |
| 分類 | **仕様指示**（この一点に限れば、統計的にはむしろ全曲共通化案の方が問題(WRの不安定性)を解消できていた） |
| 根拠 | ユーザーレビューでの明示的な判断（原典の定義を維持することを優先）。この判断により、「WR更新で無関係な他人のBPIが動く」という原典・現行の既知の欠陥は**そのまま残っている**。恣意的というより「意図して原典を優先し、統計的な理想解を採らなかった」トレードオフとして記録されている点を明確にしておく |

## 7. gamma補正: 新設（原典にも当初提案にも存在しない）

| 項目 | 内容 |
|---|---|
| 変更後 | `z100`を曲ごと実測のままにした副作用（WRが外れ値な曲でBPIが圧縮される）を補正する指数`gamma_j`を新設 |
| 分類 | **統計的導出**（式の形自体）＋**経験的校正（パラメータ）** |
| 根拠 | `gamma_j`の算出式自体は「ratio=1で常に1^gamma=1になりBPI100=WRが保たれる」という制約を満たすよう解析的に導出されている。ただし以下は経験的な選択: `zRef`（母集団のa_i分布の**95パーセンタイル**を「かなり強いプレイヤー」の基準とする）— 90パーセンタイルや99パーセンタイルでも定性的には同じ効果が得られたと考えられ、95という数字自体に統計的な必然性は無い。`GAMMA_MIN=0.3, GAMMA_MAX=3`というクランプ範囲も、「極端な曲で式が破綻しないための安全策」として選んだ値であり、この範囲の境界値自体に理論的根拠は無い |

## 8. 単曲BPIの上限: クランプなし（未対応・既知の問題）

| 項目 | 内容 |
|---|---|
| 現状 | 下限は`-15`でクランプしているが、上限には何もクランプが無い |
| 分類 | **未対応**（意図的な設計ではなく、対応が漏れている既知の欠陥） |
| 根拠 | 実データで、DBのWR定義が古い（または破損データ）場合に`ratio>1`となり、単曲BPIが100を大きく超える実例を確認した（本セッション中に発見。詳細は本文の対話履歴参照）。総合BPIの集約はべき乗平均系のため、こうした異常値1件が総合BPI全体を大きく歪める。本採用前に対応が必要 |

## 9. 総合BPI: 単曲BPIの集約 → 潜在スキル`a_i`の推定へ（issue #304）

### 9-1. `a_i`の推定式そのもの

| 項目 | 内容 |
|---|---|
| 変更後 | `a_hat = Σsigma_j(t_ij-mu_j) / Σsigma_j²`（加重最小二乗解） |
| 分類 | **統計的導出** |
| 根拠 | ALSモデルの構造から一意に決まる最小二乗解。恣意性なし |

### 9-2. 縮小推定（shrinkage）

| 項目 | 内容 |
|---|---|
| 変更後 | `a_shrunk = num/(den+residualVariance)`（事前分布`N(0,1)`とのベイズ結合） |
| 分類 | **統計的導出** |
| 根拠 | 標準的なベイズ線形回帰の事後平均。`residualVariance`もALS残差の実測値（RMSE=0.284の2乗）を使っており、恣意的な数値ではない |

### 9-3. 総合BPIの導出方法（3案の変遷）

これが今回の変更の中で最も試行錯誤が多かった部分。

**案A（最初の実装、不採用）**: `a_shrunk`を線形にBPI化した値をそのまま総合BPIとする。
→ 実測で「得意な数曲で高スコアを出すと総合BPIが伸びる」という現行方式の性質が失われ、プレイ曲数が多い上位層ほど総合BPIが現行より下がる問題が判明（378曲プレイの上位勢で67.19→63.41等）。**実測検証で不採用と判断**。

**案B（2番目の実装、初版）**: プレイ済み曲は単曲BPIをそのまま使い、未プレイ曲だけを`a_i`からの予測値で埋めてから、現行と同じ生のべき乗平均で集約する。
→ 予測値をそのまま使うと「1曲だけ全一・残りは未プレイ→総合50」という原典由来の性質が約85まで崩れることが判明。これを緩和するため、未プレイ曲の予測値を`-15`とブレンドする信頼度重み付け`w = den/(den+C)`を導入し、初版では**`C=1`という具体的な数値を、上記の「50」不変性がほぼ成り立つ点を基準に試行錯誤（0.01, 0.05, 0.1, 0.2, 0.5, 1, 2, 5, 10, 20, 50を試す）で選んでいた**。

> **【解消済み】この`C=1`は当初、本ドキュメントで最も恣意性が残る箇所として指摘していた。** その後、`w = den/(den+C)`という式の意味を改めて検討したところ、これは`a_i`の事後分散`sigma_eps²/(sigma_eps²+den)`の補数（`1 - 事後分散`＝「事後分布がどれだけ確信を持てているか」）とまったく同じ形であることに気付いた。つまり`C = sigma_eps²（=residualVariance、ALS残差から実測済みの値）`と置けば、**新たな自由パラメータを一切追加せずに済む**。実装をこの形に修正し、`UNPLAYED_FILL_PRIOR_WEIGHT`という専用定数は削除した。
>
> 実測で確認した効果: 母集団全体の分布（崖の解消・上位勢の水準）は`C=1`のときとほぼ変わらない（`[-15,-10)`帯は変わらず35人、上位5人の総合BPIも小数点以下の差）。変わるのは「1曲全一+残り未プレイ」の値だけで、50→58程度になる。これは望ましい副作用と判断している: 歴代全一（WR）の到達難度は競技人口の増加や記録更新の蓄積で当時（原典の`k=log2(n)`設計時点）より着実に「煮詰まって」おり、WRを1つ持っていることの実力的な意味は昔より重い。新モデルが実測データからそのまま導く58という値は、この実情を素直に反映した結果であり、「50」という数値そのものが今も維持すべき絶対的な基準ではないことの表れと捉えている

**案C（最終実装、現状）**: 案Bの「未プレイ曲埋め」はそのまま採用しつつ、集約方法を生のべき乗平均から**issue #297のシフト法**に差し替えた。
→ 案Bの生のべき乗平均は正側だけでなく負側でも極値に支配される性質を持つため、プレイ曲数が多く実力がやや平均以下程度のプレイヤーでも、-15床の単曲BPIが数曲あるだけで総合BPIが-15付近まで落ち込む「壁」ができていた（実測: `[-15,-10)`帯に326人）。シフト法（`k'=ln(n)/ln((100+c)/(50+c))`）に差し替えることでこれを解消（同帯35人まで減少）。

| 項目 | 内容 |
|---|---|
| 分類 | シフト法の式自体は**統計的導出**（`k'`は「50不変性」を厳密に満たすよう解析的に逆算されている、issue #297で既に検証済み）。ただし「新総合BPIの集約にはシフト法を使うが、現行/単曲のみ新方式の集約には使わない（生のべき乗平均のまま）」という**使い分け自体は本セッションでの設計判断**であり、恣意性というより「何を『現行の再現』とし、何を『新方式の一部』とするかの線引き」の問題 |

## 10. データ品質フィルタ（本ドキュメント作成時点では未実装）

分析中に、理論値を超える不正なスコア（`exScore > notes*2`）が実データに存在し、新方式のBPIを極端に歪めることを確認した。**現時点では分析用スクリプト側でのみ除外しており、`NewBpiCalculator`本体にはこのガードが入っていない。** 本採用前に対応が必要な既知の欠落。

## 総括: 恣意性の所在

| 恣意性の程度 | 該当箇所 |
|---|---|
| **恣意性なし（統計的に一意）** | `t`の定義、ALS推定式、`a_i`の最小二乗解・縮小推定式、gamma補正の式の形、シフト法の`k'`、~~未プレイ曲埋めのブレンド定数~~（`C=residualVariance`に統一、専用の自由パラメータを削除）、ALSの反復回数（固定60回→収束判定に変更） |
| **恣意性は小さい（実務上の妥当な選択）** | `z0`に中央値を使う点、母集団統合時のクロール優先ルール |
| **恣意性が残る（要再検討）** | `minSongsPerPlayer=10`、`zRef`の95パーセンタイルという選択、`GAMMA_MIN/MAX=[0.3,3]` |
| **数式上は不採用（仕様判断）** | `z100`の全曲共通化（原典の「BPI100=WR」定義を優先し見送った） |
| **未対応の既知の欠陥** | 単曲BPIの上限クランプ、不正スコアに対する本体側のガード |

**結論**: 骨格（分布モデルへの置き換え、縮小推定、シフト法の流用）に加え、当初最も恣意的だった未プレイ曲埋めのブレンド定数も、既存の統計量（ALS残差分散）をそのまま転用する形に直すことで自由パラメータを削除できた。副作用として「1曲全一+残り未プレイ→総合50」という原典由来の目印は50→58程度にずれるが、これはWR到達難度が原典設計時点より上がっている実情を新モデルが素直に反映した結果であり、意図して許容している。残る恣意性は`minSongsPerPlayer=10`・`zRef`の95パーセンタイル・`GAMMA_MIN/MAX`の3点で、いずれも「結果に大きな感度を持たない運用上の閾値」の域を出ないことを確認済み（`zRef`はgamma補正の効き方の基準点、`minSongsPerPlayer`はALS学習データの品質ゲート、`GAMMA_MIN/MAX`は破綻防止の安全域）。本採用前に優先すべきは、恣意性の解消よりも**未対応の既知の欠陥**（単曲BPIの上限クランプ、不正スコアへのガード）の方だと判断する。
