## 1. PGF（Pika-Great-Function）

「あるスコアレートを出すには何ノーツに1回黄グレ（GREAT）を出せばよいか」を表す関数。スコアレート `x'`（0〜1）に対して

```
PGF(x') = 1 + (x' - 0.5) / (1 - x')
```

と定義される。式を整理すると

```
PGF(x') = 0.5 / (1 - x')
```

になる（`1 + (x'-0.5)/(1-x') = [(1-x') + (x'-0.5)] / (1-x') = 0.5/(1-x')`）。生スコア `s` とノーツ数由来の理論値 `m` で書き直すと `x' = s/m` なので

```
PGF(s, m) = m / (2 * (m - s))
```

となる（bpim2の実装 `pgf(j, m)` はこの生スコア版）。`x' → 1`（理論値に漸近）で発散する。

**例（原典より）**: スコアレート90%を出すには何ノーツに1回黄グレを出せるか。`PGF(0.9) = 1 + (0.9-0.5)/(1-0.9) = 5`。2000ノーツの曲なら5ノーツに1回GREATを出すと`PG:1600, GR:400`となりスコアは`1600*2+400=3600=2000*2*0.9`で一致する。

`x'=1`（理論値ちょうど）はゼロ除算になるため、原典・bpim2実装とも例外的に `PGF(1) = m * 0.8` などの有限値を返す（bpim2: `pgf(j,m)`で`j===m`のとき`m*0.8`）。場当たり的な定数だが、GREAT 1個（`s = m-1`）のとき `PGF = m/2` なので `0.8m > 0.5m` となり単調性は保たれる。

## 2. 単曲BPI

### 2.1 原典の定義

皆伝平均 `k`・歴代全一 `z`・自分のスコア `s` それぞれのスコアレートをPGFに通し、皆伝平均基準で規格化する。

```
S = PGF(s/m),  K = PGF(k/m),  Z = PGF(z/m)
S' = S / K,    Z' = Z / K
```

そのまま`100 * S'/Z'`とすると、全一のスコアレートが極端に高い曲（易しい曲）では辛くなりすぎ、逆に全一のスコアレートがそこまで高くない曲では甘くなりすぎるため、`S'`・`Z'`の自然対数を取り、その比 `ln(S') / ln(Z')` を1.5乗する（原典が固定で採用した指数）。

```
単曲BPI = 100 * (ln(S') / ln(Z'))^1.5           (s >= k)
単曲BPI = -100 * (-ln(S') / ln(Z'))^1.5          (s < k)
```

自然対数を使うことで `s = k`（皆伝平均ちょうど）のとき `ln(S') = ln(1) = 0` となり、単曲BPI=0が保証される。指数1.5により、単曲BPIが高くなるほど1点の重みが増す（原典の例: BPI 0→10点に177点必要な曲で、BPI 90→100点は8点で済む）。

### 2.2 bpim2の現行実装

`BpiCalculator.calc`（[`src/lib/bpi/index.ts`](../src/lib/bpi/index.ts)）は上記と同じ骨格だが、指数を固定の1.5ではなく **曲ごとに個別に校正された `coef`** に置き換えている（`coef`の算出は§3）。

```
_k  = PGF(k, m)
_s_ = PGF(s, m) / _k
_z_ = PGF(z, m) / _k

logS = ln(_s_)         (s >= k)
     = -ln(_s_)         (s < k)
logZ = ln(_z_)

単曲BPI = sign * |logS / logZ|^coef * 100     (sign = +1 if s>=k else -1)
```

`coef`が未設定・0以下の場合は既定値`1.175`（原典の1.5から実測に基づき調整された値）にフォールバックする。

端点・例外の扱い（原典に明記の無い、bpim2独自の実装上の判断）:

- `k`（皆伝平均）または`z`（全一）が未設定、あるいは`notes=0`の譜面 → `-15`
- `s > m`（理論値超過、通常発生しない） → `null`
- `s < 0` → `-15`
- `logZ ≈ 0`（全一がPGF規格化後に皆伝平均とほぼ一致する退化ケース） → `0`
- 計算結果は下限`-15`でクランプ（§6参照）

### 2.3 逆算（`calcFromBPI`）

目標BPIから必要なEXスコアを逆算する場合は上記を逆順に解く。

```
inner = sign(targetBpi) * |targetBpi/100|^(1/coef) * logZ
_s = _k * exp(inner)
s  = m * (_s - 0.5) / _s        (PGFの逆関数: PGF(x')=v ⟺ x' = (v-0.5)/v)
```

## 3. 曲ごとの補正係数 `coef`（`p`値）の算出

原典は指数を全曲共通の1.5固定としていたが、bpim2の定義生成パイプライン（BPIM2-AutomatedDefinitionCalculator、別リポジトリ）は**曲ごとに実データから`coef`を校正**する（`calculatePValue`）。これは「原典に対するbpim2独自の拡張」であり、原典本文には登場しない。

```
upper = { 皆伝平均超え かつ 理論値以下 のスコア群 }
avgS  = upperの平均

_k = PGF(kaidenAvg, max)
_z = PGF(wr, max)
_s = PGF(avgS, max)

ratio = ln(_s/_k) / ln(_z/_k)     // 「上位平均が全一に対してどの程度の位置にあるか」

N  = max(2, upperの件数)
E[BPI](N) = 100/ln(N) - 100/(N-1)     // 皆伝平均超えN人の期待値上位平均が持つべきBPIの経験式
targetBpiRatio = E[BPI](N) / 100

p = ln(targetBpiRatio) / ln(ratio)
coef = clamp(p, 0.5, 2.5)             // 極端な値による破綻を防ぐクランプ
```

`upper`が空、`wr <= kaidenAvg`、`ratio`が0以下・1以上、`p`がNaN、のいずれかに該当する場合は既定値`1.175`にフォールバックする。

この`coef`算出は「皆伝平均超えスコアの上位平均という1つの要約統計量から、曲ごとの分布の歪みを表す指数を逆算する」構造になっている。issue #301はこの構造を「分布そのもの（`sigma_j`）から解析的に決定する」方式へ置き換える提案だったが、検証時点では未着手（決定記録0005参照）。

## 4. 総合BPI

### 4.1 原典の定義

単純平均だと、他の曲が未プレイでも1曲だけ全一を持つ人が著しく低い総合BPIになってしまう問題がある。これを避けるため、符号付きのべき乗平均（二乗平均平方根の一般化）を使う。

```
n = 対象譜面数
k = log2(n)                          // べき乗平均の指数
BPI_1, ..., BPI_n = 各曲の単曲BPI（未プレイは-15で埋める）

総合BPI = ( Σ_{a=1}^{n} BPI_a^k / n )^(1/k)
```

`k = log2(n)`と置くことで「1曲だけ全一を持ち、残りが全て未プレイ（-15）」の人の総合BPIがちょうど50になるという性質を満たす（原典が意図的に設計した性質）。導出は1行: `n^(1/log2 n) = exp(ln n · ln2/ln n) = 2` なので、負項（-15、`n=650`で相対 `1e-5` 程度しか効かない）を無視すれば `(100^k / n)^(1/k) = 100 / n^(1/k) = 100 / 2 = 50`。

単曲BPIが負の場合はそのまま`k`乗すると実数域で定義できないため、原典は

```
sign(BPI_a) * |BPI_a|^k
```

という符号付きの拡張を使う（bpim2の実装と同じ）。さらに、下限を大きく割り込む曲に総合BPIが引っ張られすぎる問題について、原典は「こういう工夫が必要だと思うが一旦放置している」として次の3案を列挙している（原典自身はいずれも未実装）。

- 単曲BPIの下限を-15とする（十段平均に相当する値として）
- そもそも負の単曲BPIを除外して計算する
- 単曲BPIの下限値の絶対値を全単曲BPIに加算してから計算し、後で引く（本ドキュメント・issue #297 で言う「シフト法」。原典に手法の記述はあるが、この呼称は bpim2 側のもの）

原文（[3]総合BPIの求め方）:

> しかしながら、これだと大きく皆伝平均を下回る曲があるとそれに引っ張られてしまうため、負の単曲BPIを含む総合BPIの計算を行うときには、（中略）|単曲BPIの下限値|を全ての単曲BPIに加え計算し|単曲BPIの下限値|を引く などの工夫をする必要があると思っておりますが、本来BPIはランカーさんの実力を評価するものであるため、この問題に関しては一旦放置しております。

### 4.2 bpim2の現行実装

`BpiCalculator.calculateTotalBPI`は原典の定義をそのまま実装している（シフト法などの改良は未適用）。

```
k = max(1, log2(n))

sum = Σ_{i=1}^{n} sign(BPI_i) * |BPI_i|^k / n      (未プレイはBPI_i = -15として埋める)
総合BPI = sign(sum) * |sum|^(1/k)
```

これは符号付きべき乗平均（`k`乗して平均し、`1/k`乗して戻す。符号が打ち消し合うため厳密には「ノルム」ではなく、この打ち消しが問題の本体）であり、原典自身が示唆した次の問題をそのまま抱えている（issue #297で実測・詳細分析）。

- `k`が大きい（曲数が多い）ほど `Σ sign(BPI_i)|BPI_i|^k` は絶対値最大の1曲に支配される
- `sign(sum)·|sum|^(1/k)` は `sum=0`（正負が拮抗する点）で**値としては連続だが微分が発散する**（`|sum|^(1/k-1) → ∞`、`k>1`）。跳び（不連続）ではないが、符号反転点付近では 1曲のスコアが 1 点動くだけで総合が二桁動く。`n=650`（`k≈9.34`）で「1曲だけ正・残り649曲が-15」を考えると `sum≈0` は 1曲側 `BPI ≈ 15·649^(1/k) ≈ 30` 付近で、そこを 29→30→31 と動かすと総合は概ね -13.0 → 0 → +13.4 と動く（issue #297の実測「1曲+1で総合が最大+21」もこのオーダー。「断崖」という比喩は使うが、正しくは「連続だが勾配が発散」）

### 4.3 [参考] シフト法（issue #297 → クローズ。新方式が採用）

§4.1 で原典が「工夫が要る」として列挙した3案のうちの1つ（下限値の絶対値を全BPIに加算 → 計算 → 引く。原典自身は未実装）を、`BPI=100@全一, BPI=50@1曲全一+残り未プレイ`という原典の性質を崩さない形に仕上げたもの。

```
c  = 15                                    // 単曲BPIの下限の絶対値
k' = ln(n) / ln((100+c)/(50+c))            // シフト後も上記の性質を維持するための再校正指数
総合BPI = ( Σ_i (BPI_i + c)^k' / n )^(1/k') - c
```

`k'`の再校正は「シフトすると`n^(1/k)=2`という性質が崩れるため、`n^(1/k') = (100+c)/(50+c) = 115/65` となるよう解き直す」という設計判断に基づく。これにより「1曲全一（100）＋残り未プレイ（-15）」は `(115^k'/n)^(1/k') - 15 = 115/n^(1/k') - 15 = 115/(115/65) - 15 = 65 - 15 = 50` で厳密に50、全曲全一なら `115 - 15 = 100`。`n=650` で `k' ≈ 11.35`（原典の `k = log2(650) ≈ 9.34` より大きい＝より上位曲支配寄り）。

issue #297 は現行 `BpiCalculator` への適用を `feat/total-bpi-cliff-fix` ブランチ（コミット `48f60a4`）に試作したが、**新方式への移行に一本化するため PR #312 ともどもクローズ**（現行 `BpiCalculator.calculateTotalBPI` は §4.2 の旧実装のまま）。新方式の総合BPI集約（§7.5）がこのシフト法を採用している。

## 5. 順位推定（`estimateRank`）

単曲BPI・総合BPIから、原典が独自に設定した基準人数（皆伝取得者数5,232人の半数=2,616位）を使って全国順位を推定する。「BPIが10点下がるごとに順位が一定倍率で悪化する」という指数モデル。`BPI=0`（＝皆伝平均スコア）をこの中央順位に対応づけているのは、皆伝プレイヤー内で「平均スコア ≈ 中央順位」を暗黙に仮定している。

```
単曲順位 = 2616 ^ ((100 - 単曲BPI) / 100)
```

bpim2の`estimateRank`（総合BPI版）は

```
順位 = ceil( AVERAGE_OF_ALL_KAIDENS ^ ((100 - 総合BPI) / 100) )
```

（`AVERAGE_OF_ALL_KAIDENS = 2699`。原典は総合BPI版の基準点をDOLCE.氏の実測総合BPI≈95から経験的に求めていたが、bpim2実装は単曲BPI版と同じ指数系を流用している）。

### 5.1 新方式の順位推定（`NewBpiCalculator.estimateRank`）

原典・現行実装の順位推定式は、いずれも実測データ1点（皆伝取得者数、DOLCE.氏のBPI）から逆算したパラメトリックな指数モデルである。新方式では、アリーナクロールデータに含まれる実際の順位（`players.json`の`rank`フィールド）と、同一プレイヤーの潜在能力`a_i`の実測ペア（現行の生成物では 2026-03-21 + 2026-05-26 クロール統合で約1.5万件）を使い、**経験分布から直接カーブを作る**（正規分布等のパラメトリックな仮定を置かない）。

```
1. 各クロールシリーズについて、(順位 / そのシリーズのロスター人数) をパーセンタイルとする
   （シリーズごとにロスターの規模が変わるため、絶対順位ではなく比率で正規化する）
2. (パーセンタイル, a_i) のペアをパーセンタイル昇順に50ビンに分割し、ビンごとの中央値を取る
3. 単調性の補正（isotonic regressionの簡易版）: パーセンタイルが大きくなるほどaが
   小さくなるよう、先頭からの累積最小値を取る
4. 実行時は、推定したa_iからこのカーブを二分探索・線形補間してパーセンタイルを求め、
   z0算出時と同じ基準人数（アリーナA帯在籍者数）を掛けて絶対順位に変換する
```

実測でのパーセンタイルと`a_i`のスピアマン順位相関は概ね-0.7（強い負の相関、期待通り。アリーナ順位はBPI以外の要素（プレイ量・勝率等）も反映するため完全一致は理論上も期待できない）。

## 6. 負のBPI・下限について

原典は次のように明言している（意訳せず要点を引用）:

> 全ての人が皆伝平均を超えたスコアを出すことはできない。総合BPIの計算の際に下限を-15（だいたい十段平均）とすることを推奨しているが、負の領域に関しては想定とは異なる数値が出力されてしまうと考えている。

つまり、負のBPI・-15という下限は「原典自身が精密な設計をしていないと認めている領域」である。bpim2は単曲BPI・総合BPIの両方で`-15`を実装上の下限として採用しているが、この値自体の妥当性・尺度としての性質（z尺度かr尺度か）は検証中（issue #303、決定記録0005で今回のスコープ外として保留）。

## 7. 検証中の新方式（分布ベース、issue #299系）の数学

### 7.1 動機とモデル

原典・bpim2の現行実装は「皆伝平均」「全一」という2点のアンカーと、曲ごとに校正した`coef`という3パラメータで曲の形状を表現している。これに対し新方式は、曲ごとに実際のスコア分布を測定し、位置（`mu_j`）と弁別力（`sigma_j`）という2パラメータで直接表現する。

まず、原典のPGFをそのまま対数化した量`ln(PGF(x'))`と、新方式が使う`t = -ln(m - s)`は、次の関係にある。

```
PGF(x') = 0.5 / (1 - x')
ln(PGF(x')) = -ln(2) - ln(1 - x')
t = -ln(m - s) = -ln(m) - ln(1 - x')     (∵ m - s = m(1 - x'))

t - ln(PGF(x')) = ln(2 / m)     （曲固有の定数）
```

つまり`t`は原典のPGFの対数と本質的に同じ量で、差は曲ごとの定数`ln(2/m)`だけである。新方式のALS推定はこの定数を`mu_j`（曲の位置パラメータ）が自動的に吸収するため、`t = -ln(m-s)`をそのまま使ってよい。

潜在スキルモデル:

```
t_ij = mu_j + sigma_j * a_i + ε_ij

a_i     … プレイヤーiの潜在スキル（1人1スカラー。母集団全体で平均0・分散1に正規化）
mu_j    … 曲jの位置（難度）
sigma_j … 曲jの弁別力（スキル差がスコア差にどれだけ表れるか）
ε_ij    … 残差（測定ノイズ）
```

### 7.2 ALS（交互最小二乗）推定

`mu_j`・`sigma_j`・`a_i`を交互に更新して収束させる（[`scripts/generate-new-bpi-params.ts`](../scripts/generate-new-bpi-params.ts)）。

```
1. mu_j, sigma_j を観測されたt_ijの平均・標準偏差で初期化
2. a_i = Σ_j sigma_j(t_ij - mu_j) / Σ_j sigma_j²    （原点を通る単回帰の最小二乗解。sigma_j は重みではなく説明変数。プレイ済み曲のみ）
3. {a_i} を平均0・分散1に正規化（スケールの不定性を固定するため）
4. 曲ごとにt_ijをa_iへ単回帰し、mu_j・sigma_jを更新
5. 2〜4を反復。a_iの反復間の最大変化量が母集団SD（=1）の0.01%を下回った時点で打ち切る（上限500回、実測では数反復で収束）
```

正規化（手順3）はスケールの不定性は固定するが**符号の不定性（`a→-a, sigma→-sigma`）は固定しない**。手順1で sigma_j を標準偏差（正）で初期化するため、実質的には「a_i が大きいほど上手い」向きに定まる。

適合度は決定係数`R² = 1 - Σ(t_ij - pred_ij)² / Σ(t_ij - t̄)²`で評価する。現行の生成物（`src/constants/iidx/newBpi/songParams.json`、`sourceVintage: "2026-spring (03-21 + 05-26 crawl merge)"`）は 2026-03-21 と 2026-05-26 のアリーナ上位クロールを統合した母集団（5,329人、対象1,298曲、☆11+☆12）で、`R²=0.861`、残差の標準偏差（RMSE）は`0.294`（t単位）。この母集団は現行BPIの`coef`定義が校正されたのと同じ時期のクロールで、新旧の比較を同時期のデータで行えるようにしている（初版検討時の2026年9月スナップショット（クロール+bpim2ユーザー、5,942人・1,300曲）では`R²=0.891`/RMSE`0.284`）。

### 7.3 z尺度BPIとアンカー

推定された`mu_j, sigma_j`を使って、スコアを曲固有の潜在能力位置`z`に変換する。

```
z_ij = (t_ij - mu_j) / sigma_j
```

`z`は「その曲において、このスコアが母集団の能力分布上どの位置に相当するか」を表す（単位は母集団の標準偏差）。これを2つのアンカーで0〜100に再スケールする。

```
BPI_ij = 100 * (z_ij - z0) / (z100_j - z0)
```

- `z0`（BPI=0のアンカー）: 決定記録0005により**全曲共通の定数**を採用。当初は「各曲の皆伝平均のz位置の全曲中央値」（実測`z0 ≈ -0.132`）としていたが、「皆伝を取っていなくても上手いプレイヤーはいる」という指摘を踏まえ、皆伝合格という関門を経由しない指標に変更した（決定記録0007）。現在は**アリーナA帯（a1〜a5）在籍者の潜在能力`a_i`の中央値**（現行の生成物で実測`z0 ≈ -0.212`。初版は`-0.193`）を使う。平均ではなく中央値を使うのは、A帯在籍が総合的な立ち回り（勝率・プレイ量等）で決まり☆11/12最難関の実力だけでは決まらないため、分布が右に歪んでおり（少数の突出したプレイヤーが平均を引き上げる）、中央値の方が「A帯在籍者の典型的な実力」を代表するため
- `z100_j`（BPI=100のアンカー、全一相当）: 「BPI100=歴代全一」という原典の定義を崩さないため、**曲ごとに実際のWRスコアから都度計算する**（全曲共通定数にはしない。決定記録0005参照）

### 7.4 gamma補正の導出

`z100_j`を曲ごとの実測値のままにした副作用として、一部の曲でWRが母集団から見て極端な外れ値（統計的に見て「多くのプレイヤーが高スコアを出しているだけで、実際には簡単ではない」曲）になり、そのままでは単曲BPIの伸びが不自然に圧縮される。

これを、**全曲同一の式・同一の全曲共通定数**から曲ごとに解析的に決まる指数`gamma_j`で補正する。

```
z_ref            … 母集団の潜在スキルa_iの95パーセンタイル（「かなり強いプレイヤー」の基準位置、全曲共通の定数）
gap_typical      = z100_typical - z0     （z100_typical: z100_jの全曲中央値、参考値）
gap_j            = z100_j - z0           （この曲の実際のgap）

r_typical = (z_ref - z0) / gap_typical
r_j       = (z_ref - z0) / gap_j

gamma_j = ln(r_typical) / ln(r_j)
gamma_j をクランプ [0.3, 3]
```

意味: 「典型的なgapの曲でz_refのプレイヤーが到達するBPI相当の位置」に、この曲でも同じz_refのプレイヤーが到達するよう、曲間で`r^gamma`の傾きを揃える。`r_typical`・`r_j`のいずれかが0以下または1以上（アンカーの外側・退化ケース）の場合は`gamma_j=1`（補正なし）にフォールバックする。

BPIの最終式（gamma込み）:

```
ratio = (z_ij - z0) / (z100_j - z0)
BPI_ij = 100 * sign(ratio) * |ratio|^gamma_j
```

`ratio=1`（`z_ij = z100_j`、つまりスコア=WR）のとき`|1|^gamma_j = 1`となるため、**`gamma_j`の値に関わらずBPI=100（WR）は式の性質上厳密に保たれる**。これがissue #302の「BPI100=WRを維持したまま曲ごとの歪みを緩和する」という要求を満たす鍵になっている。

なお `z0`・`z_ref` は `a_i` 分布（分散1）上に定義した量、`z_ij` は `a_i + ε_ij/sigma_j` で分散が `1 + σ_ε²/sigma_j²` と曲ごとに異なる量であり、両者を同一の `z` 軸として扱うところに小さな尺度の不整合がある（弁別力の低い曲ほど `z_ij` のばらつきが大きい）。gamma補正は期待値ベースの位置合わせなので実用上は問題にならないが、厳密には残差込みの尺度差である。

#### 7.4.1 信頼度重み付け（決定記録0008）

上記の`gamma_j`は「典型的なgapからのズレ」に連続的に反応するため、真に外れている曲（初版検討時の実測: 対象1,300曲中45曲程度、IQR基準では650曲中36曲）だけでなく、中央値から少しでもズレていれば大多数の「普通の曲」にも補正がかかってしまう（同: 650曲中325曲がgamma>1になり、弁別力`sigma_j`が高い「地力譜面」でこの副作用が特に目立った）。

これを補正するため、`z100_j`の中央値からのズレを、曲間の自然なばらつき（`z100`分布の四分位範囲IQR）を物差しにして測り、その2乗を信頼度重みとして`gamma_j`の効きを減衰させる。

```
d      = |z100_j - z100_typical| / IQR(z100)
weight = d² / (d² + 1)

gamma_j_final = 1 + weight * (gamma_j - 1)
```

`d`が小さい（曲間の自然なばらつきに収まる）曲ほど`weight→0`となり`gamma_j_final→1`（無補正）に、`d`が大きい（明確な外れ値）曲ほど`weight→1`となり素の`gamma_j`に近づく。曲ごとの観測数から求まる推定誤差を物差しにする案も検討したが、観測数が多い曲ほど推定誤差が小さくなり、僅かなズレでも「統計的に有意」と判定されてしまうため採用しなかった（決定記録0008参照）。

### 7.5 総合BPI: 測定値 + 未プレイ曲のa_i予測埋め + シフト法（issue #304 / 決定記録0006）

**不採用だった案A**: プレイヤーの潜在スキル`a_i`を全プレイ済み曲から直接推定し、`100 * (a_shrunk - z0) / (z100_typical - z0)` でそのままBPI化する。この案は「得意な数曲で高スコアを出すと総合が伸びる」という現行方式の性質（べき乗平均由来）を失い、プレイ曲数が多い上位層で総合BPIが現行より下がる問題があったため不採用（決定記録0006）。

**採用した集約**（`NewBpiCalculator.calculateTotalBPI`）:

1. **プレイ済み曲**: 単曲BPI（§7.4、gamma込み）をそのまま使う
2. **未プレイ曲**: 潜在スキル`a_i`の縮小推定値から予測し、信頼度でブレンド
3. **全曲**（1 + 2）をシフト法（§4.3）のべき乗平均で集約

**a_iの縮小推定**（未プレイ曲の予測に使う）: 素の最小二乗解 `a_hat = num/den`（`num = Σ_j sigma_j(t_ij - mu_j)`、`den = Σ_j sigma_j²`。§7.2 と同じ、原点を通る単回帰の解）を母集団事前分布 `a_i ~ N(0, 1)`（ALS推定でこの分布へ正規化済み）とベイズ結合する。

```
事前:   a_i ~ N(0, 1)
尤度:   a_hat | a_i ~ N(a_i, residualVariance / den)     (residualVariance = ALS残差の分散、t単位)

a_shrunk = num / (den + residualVariance)
```

標準的なリッジ型の縮小で、`den`（弁別力の高い曲を多くプレイしているほど大きい）が十分大きいユーザーは素の`a_hat`に、`den`が小さいユーザーは事前平均0（母集団平均）へ連続的に寄る（境界での不連続なし）。

**未プレイ曲 j の予測とブレンド**:

```
BPI_pred_j = (a_shrunk を z として §7.4 の単曲式に通した値)
w          = den / (den + residualVariance)            // 事後分散（=residualVariance/(residualVariance+den)）の補数。事前分散が1なので成立
BPI_j^blend = w * BPI_pred_j + (1 - w) * (-15)          // 観測が少ないほど下限側へ寄る
```

`w` の関数形（`den/(den+residualVariance)`）は §7.4.1 の gamma 信頼度重みと同じ「情報量 / (情報量 + 疑い)」の枠組みで、`residualVariance` は ALS 出力から決まる。

補足（設計判断として明記）: この方式は実質的に **二段の縮小**になっている。`a_shrunk` の時点で既に母集団平均へ寄せた上で、さらに `(1-w)` で `-15` へブレンドしている。しかも 2 段目の寄せ先は「事前分布 `a_i~N(0,1)` が含意するBPI（≒ `z0` 相当）」ではなく `-15` という別の定数であり、これは現行方式の「未プレイ＝-15」の発想を引き継いだ選択（＝ `-15` 自体は選ばれたパラメータ）。「新たなチューニング用の自由パラメータを追加していない」（`residualVariance` は実測、`-15` は既存の下限）という意味で自由度は増やしていないが、寄せ先の選択という設計判断は入っている。

**集約**（シフト法、§4.3 と同じ）:

```
c  = 15
k' = ln(n) / ln((100+c)/(50+c))
総合BPI = ( Σ_i (BPI_i + c)^k' / n )^(1/k') - c
```

`BPI_i` はプレイ済み曲の単曲BPIと未プレイ曲のブレンド値、`n` は ☆12 全曲数。全項に `c=15` を加えて非負にしてから集約するため、§4.2 で問題になった「符号反転点（`sum≈0`）で微分が発散し 1曲 +1 で総合が二桁動く」現象（「断崖」）は起きない（`(BPI_i+c)` が常に非負で、`sum=0` 近傍を通らない）。ただし `k'` は依然大きい（`n≈650` で `k'≈11.35`、原典の `k≈9.34` より大きい）ため、「総合BPIが現在の水準以上の曲に支配される」性質は部分的に残る（複合検証で確認済み）。

## 8. 対応表

| 概念 | 原典 | bpim2現行実装 | 新方式（検証中） |
|---|---|---|---|
| 単曲BPIの基礎量 | `ln(PGF(x'))` | 同左 | `t = -ln(m-s)`（本質的に同じ量、§7.1参照） |
| 曲の形状パラメータ | なし（固定指数1.5） | `coef`（曲ごとに上位平均から逆算） | `mu_j, sigma_j`（曲ごとの分布から直接推定） |
| BPI=0のアンカー | 皆伝平均（曲ごとの実測） | 同左 | 全曲共通の定数`z0`（アリーナA帯在籍者の典型的実力の中央値、決定記録0007） |
| BPI=100のアンカー | 全一（曲ごとの実測） | 同左 | 曲ごとの実全一（`z0`のみ共通化。決定記録0005） |
| 曲間の歪み対策 | なし | `coef`のクランプ[0.5, 2.5] | `gamma_j`補正（決定記録0005） |
| 総合BPIの集約 | 符号付きべき乗平均、`k=log2(n)` | 同左 | プレイ済みは単曲BPI・未プレイはa_i予測(縮小推定+信頼度ブレンド)で埋め、シフト法で集約（決定記録0006、§4.3のシフト法） |
| 負のBPI・下限 | -15を推奨、詳細は「一旦放置」 | -15でクランプ | 暫定的に-15でクランプ（尺度の正式決定はissue #303で保留中） |
