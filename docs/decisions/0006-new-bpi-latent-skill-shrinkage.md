# 0006: 潜在スキルa_iによる総合BPI直接算出における縮小推定の採用

- **ステータス**: 採用
- **記録日**: 2026-09-05
- **対応issue**: #311（決定記録0005の「不採用・保留」項目のうち、総合BPIのa_i直接推定を覆す）

## 背景

決定記録0005で、単曲BPIの分布ベース再定義（旧epic #299由来）のうち、総合BPIを潜在スキル`a_i`の直接推定に置き換える案（旧#304）は「shrinkage未実装のため本採用せず、試作のみ」として不採用・保留にした。

`a_i`の加重最小二乗解（`a_hat = Σ_j sigma_j(t_ij-mu_j) / Σ_j sigma_j²`）は、プレイ曲数が少ないユーザーほど分散が大きくなり、値が不安定になる。この項目のみ、shrinkageの実装によって解消できる見込みが立ったため、0005の判断を本記録で更新する。

## 検討した選択肢

| 案 | 概要 |
|---|---|
| A: 素の最小二乗解のまま採用しない | 0005時点の判断。値の不安定さがユーザーへの説明を難しくするため保留 |
| B: 事前分布への縮小推定（ベイズ結合） | `a_i ~ N(0,1)`という事前分布（ALS推定時の正規化そのもの）と、尤度`a_hat ~ N(a_i, residualVariance/den)`をベイズ結合し、事後平均`a_shrunk = num / (den + residualVariance)`を使う。追加のパラメータ調整（縮小の強さを手動チューニングする等）が不要で、既存のALS出力（残差RMSE）だけから閉じた式で導出できる |
| C: 曲数の閾値でカットオフ | 一定曲数未満のユーザーは`a_i`推定自体を提供しない | 単純だが閾値前後で不連続な扱いになり、境界のユーザーへの説明が難しい |

## 結論

B案（事前分布への縮小推定）を採用する。

- 事後平均 `a_shrunk = num / (den + residualVariance)` を`NewBpiCalculator.estimateLatentSkill()`として実装した。`residualVariance`はALS残差の分散（t単位）で、`scripts/generate-new-bpi-params.ts`が算出し`songParams.json`の`residualRmse`として出力する（実測: RMSE=0.284、母集団5,942人、対象1,300曲）
- C案は却下。曲数閾値という新たな恣意的パラメータを追加することになり、B案のようにALS推定から自然に導出できる利点がない
- これにより決定記録0005の「総合BPIをa_i直接推定に置き換える件（旧#304）」は不採用から採用に変わる。0005の他の判断（mu/sigmaのJSON格納、z0/z100ハイブリッド、gamma補正、coefのsigma_j化の見送り、尺度全面移行の保留）は変更しない

## 影響

- `src/lib/bpi/newBpi.ts`に`estimateLatentSkill()`/`calculateTotalBPI()`を実装し、`/api/v1/new-bpi/players`・`/new-bpi`「一覧」タブで重複していた同等ロジックをこの共通実装に統一した
- 曲数が少ないユーザーほど総合BPIが0（母集団平均相当）に近づき、多いユーザーほど素の推定値に漸近する。境界での不連続は生じない
