# 0012: 単曲BPIのカーブ指数 — 3アンカー／傾き一致案の検証と不採用（決定記録0011を追認）

- **ステータス**: 不採用（[決定記録0011](0011-new-bpi-curve-exponent-coef.md) の全域 `k = clamp(gamma_j·coef_j, 0.62, 3)` を維持）
- **記録日**: 2026-09-09
- **対応**: epic #367 配下の検討（`/new-bpi` プレビューの調整。本番BPIは未変更）。検証は dev-local スクリプト（`scripts/` は gitignore、コミット対象外）

## 背景

決定記録0011 の `k_j = clamp(gamma_j·coef_j, 0.62, 3)`（全 `ratio` 域に一様にかかる指数）は、同一潜在スキル帯のプレイヤーが曲ごとに得るBPIの散らばり（曲間BPI SD）を **強豪帯で大きく縮める**（潜在スキル最上位帯 `a_i > 1.5` で 2.72 → 1.57、総合BPI 50〜60帯で 4.23 → 2.66。Notion 効果検証 §10.6–10.8）。これは coef が担っている、線形 ALS モデル（`t = mu_j + sigma_j·a_i + eps`）が表現できない WR 直下（PGF 発散域）の曲ごとの曲率の代用によるもの。

一方、同じ全域指数のため、中位以下の帯では曲間BPI SD が現行よりわずかに増える（coef < 1 が sub-`z_ref` のスコアに per-song オフセットを持ち込む。cohort 平均で +0.1〜0.4pt）。この副作用を「補正を WR 直下に局在させる」ことで消せないか検証した。

## 検討した選択肢

| 案 | 概要 | 検証結果 |
|---|---|---|
| **3アンカー（区分べき乗）** | `z_ref`（gamma 較正点＝95パーセンタイル）に対応する `r_ref = (z_ref−z0)/(z100_j−z0)` を第3アンカーに置く。`ratio ≤ r_ref` は `k = clamp(gamma_j)`（＝coef なし）、`ratio > r_ref` は `k = clamp(gamma_j·coef_j)`。接続点で値は連続、WR=100 厳密、単調。 | 中位帯は coef なし挙動（＝現行より改善）、強豪帯の曲間SD **2.72 → 1.87**（大部分回復）。ただし **接続点で傾きが不連続**（極端曲で下側:上側 ≈ 1:6）、V 等の全一遠隔曲で上側が coef より過剰に甘くなる（WR·99.5% 相当のスコアで BPI 69.1 vs coef 64.4）。 |
| **3アンカー + 傾き一致（C1）** | 上を C1 化。①上側 `s^k` を原点シフト `(s+δ)^k` にして δ を接続点の傾き一致で決める、②指数を `r_ref → WR` で smoothstep で `clamp(gamma_j) → clamp(gamma_j·coef_j)` に遷移させる、の2通りを実装。 | 接続は滑らかになり V の過剰な甘さも解消。しかし **強豪帯の曲間SD が 2.52〜2.60 ≒ coef なし（改善ほぼ消失）**。総合BPI 50〜60帯も 3.8〜4.0（coef ありは 2.66）。原因: 強豪帯（`a_i > 1.5`）は `ratio` に直すと ≈ 0.25〜0.5 で **`r_ref` 近傍**にいるため、C1 接続＝「`r_ref` で指数を gamma 側に戻して滑らかに繋ぐ」と、その帯では指数がまだ gamma 寄りになり coef が効かない。素の3アンカーが効いていたのは接続点で傾きが跳ねて上側を積極的にできていたからで、C1 にした時点でその自由度が失われる。 |
| coef なし（`k = clamp(gamma_j)` 全域） | 決定記録0011 のアブレーション（Notion §10.8）。 | 中位帯は改善、強豪帯 2.72 → 2.61（改善なし）、単曲BPI 現行比 mean −0.34（やや辛い）。 |

いずれも `scripts/_new-bpi-3anchor-check.ts` / `_new-bpi-nocoef-check.ts`（dev-local）でローカルDB v33・☆11+☆12・1,587人・約109万スコアに対して測定。

## 結論

**決定記録0011（全域 `k_j = clamp(gamma_j·coef_j, 0.62, 3)`）を維持する。**

- **BPI は原典から一貫して上位（ランカー）評価ツール**（原典 [3] は「本来BPIはランカーさんの実力を評価するもの」と明言。−15床・べき乗平均・順位推定の基準人数 2,616＝皆伝取得者数の半数、いずれも上位前提の設計）。最も使われる強豪帯の曲間公平性（2.72 → 1.57）を出せるのは全域 `k = clamp(gamma·coef)` のみで、3アンカーを C1 にすると出せない。
- 中位以下の副作用は cohort 平均で +0.1〜0.4pt と小さく、Notion §10.6 のとおりその帯の曲間SDの残差は実在する譜面適性が主成分で、均しすぎると得意不得意まで潰す。
- 全域 `k` は単一の滑らかなべき乗で C1、`calcFromBPI` が解析的（推移グラフ用）。3アンカーは接続で折れが出る（素）か、C1 にすると coef 効果が消える（傾き一致）。
- 傾き一致と coef の効果を3アンカー構造で両立させるには、遷移ゾーンを `r_ref` より下に置く必要があり「どこから遷移を始めるか」という新しい恣意的パラメータが増える（この検討で消そうとしたもの）。

## 補足: 残差カーブ検査（`coef` の位置づけの見直し）

案A の接続点を「探索」でなく「導出」で決められないか、線形モデル `t_ij = mu_j + sigma_j·a_i + eps` の残差を直接検査した（`scripts/_new-bpi-residual-curvature.ts`、dev-local。曲IDの偶奇で split-half にし、片側から推定した `a_hat` で反対側の残差を見ることで推定の機械的直交を回避）。

プレイヤーの潜在スキル `a_hat` でビン分けした標準化残差 `e/sigma` は全域（`a_hat ≈ -1` 〜 `3`、☆11+☆12・約109万観測）で mean が ±0.02 以内でフラットだった。**強豪帯でも線形モデルは系統的に破綻しておらず、カーブが破綻し始める `a_i` の位置（＝3アンカーの接続点の物理的定義）は存在しない。** （`z_ij`（観測ごとの潜在位置）でビン分けすると `e/sigma` が 0→0.34 と単調に増えて見えるが、これは `e/sigma = z_ij - a_hat` の平均への回帰であり、`a_hat` の縮小係数（λ ≈ 0.9）から定量的に説明できる。モデルのカーブではない。）

この結果を踏まえた `coef_j` の位置づけ:

- 「`coef_j` は線形 ALS モデルに欠けた WR 直下の曲率の代用」とは**言えない**（欠けた曲率が残差検査で検出されない）。決定記録0011 当初の「移行時にカーブの体感を現行実装と揃えるための踏襲（互換性論）」という説明の方が正確。
- `coef_j` は定義生成パイプライン（BPIM2-AutomatedDefinitionCalculator）が「皆伝平均超え N 人の期待値上位平均が持つべき BPI」（`E[BPI](N) = 100/ln(N) - 100/(N-1)`）から曲ごとに逆算した、**上位コホートの目標 BPI の per-song 較正**。これを新尺度の指数に持ち込むと、上位コホートの曲間 BPI の一貫性が引き継がれる。決定記録0011 のアブレーション（`coef_j` を外すと強豪帯の曲間 SD 改善 2.72→1.57 が 2.72→2.61 に戻る）は、この引き継いだ較正が強豪帯の曲間公平性に効いている実測であって、モデル欠陥の補正ではない。
- したがって Notion 効果検証ページの §6.3 / §10.8 の「線形 ALS に欠けた曲率の代用」という表現は踏み込みすぎで、「上位コホートの曲間較正の踏襲」に弱める（本記録で留保。ページ側の修正は別途）。

`coef_j` が1統計量からの逆算である点・下限 0.62 が較正値である点（決定記録0011 の留保）は変わらない。
