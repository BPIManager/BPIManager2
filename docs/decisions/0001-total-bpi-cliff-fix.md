# 0001: 総合BPI「断崖絶壁」問題の修正方式

- **ステータス**: 不採用
- **記録日**: 2026-08-01（`docs/decisions/`運用開始（#206）に伴う遡及記録。検討自体はこれ以前に行われていた）

## 背景

総合BPI計算（符号付きべき乗平均、`BpiCalculator.calculateTotalBPI`）は、曲数が多いほど冪乗数kが大きくなるため、下位帯（BPI -15付近）のプレイヤーが1曲だけ大きく改善するだけで総合BPIが十数ポイント跳ね上がる「断崖」が発生する試算があった（例: 149曲がBPI -8のまま1曲だけBPI 15→20に改善すると、総合BPIが-6.96→+9.70に跳ぶ）。

## 検討した選択肢

| 案 | 概要 | 評価 |
|---|---|---|
| A: シフト法 | 全BPIに+15してから通常のべき乗平均を取り、結果から-15する | 断崖は完全解消するが高BPI帯（20〜100）のスケールが変わり、既存上位プレイヤーへの影響が大きい |
| B: 非対称冪指数 | 負値の寄与にだけ小さい冪指数を適用する | 断崖が別の位置（BPI 5〜10付近）に移動するだけで根本解決にならない |
| C: ソフトクリップ | 計算専用の下限値（例: -5）でクリップする | 高BPI帯は完全に無変更で保護されるが、負帯域（-15〜-5）の解像度が失われる |
| D: 負値対数圧縮 | 負のBPIのみ平方根系の関数で圧縮する | 高BPI帯に影響ゼロで断崖も解消するが、負帯域の表示値の意味が変わり逆変換が必要になる |

## 結論

不採用。4案とも一長一短があり検討時点ではD案（負値対数圧縮）が最有力候補として推奨されていたが、最終的にどの案も採用されなかった。具体的な却下理由は記録が残っておらず、試験的な検討に留まったことのみ分かっている。総合BPI計算の断崖問題自体は未解決のまま残っている。
