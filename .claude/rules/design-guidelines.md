# デザインガイドライン（余白・タイポグラフィ等のビジュアル規約）

コンポーネントの配置・余白・タイポグラフィで実際に踏んだ不具合（後述）を踏まえた、視覚的一貫性のための規約。Tailwindのキャノニカルクラス優先やshadcn/ui優先といった基本方針は`coding-conventions.md`、`src/components/partials/`のディレクトリ構成は`components.md`を参照（本ファイルでは重複記載しない）。

## 余白: 兄弟間の間隔は親の`gap-*`で決める、子に`mt-*`/`mb-*`を持たせない

- 横に並ぶ・縦に積むブロック群の間隔は、それらを包む1つのflex/gridコンテナの`gap-*`だけで管理する。個々の子要素（特に複数箇所から呼ばれる再利用コンポーネント）が自分の外側に`mt-*`/`mb-*`を持って間隔を作ってはいけない
- **理由（実例）**: `BpiOptimizer/ui/OptimizerIntro.tsx`は当初`<Alert className="mt-4 ...">`のように自前で上余白を持っていた。この結果、`gap-4`の中で使う画面（Drawer内の作成方法選択）と`gap-3`/`gap-2`の中で使う画面（`SavedMemoList`の空状態）とで実際の間隔が揃わなくなった（`gap-N` + 自前の`mt-4`が二重に効くため）。同様に`OptimizerGuide.tsx`の`<Accordion className="mt-4">`も、呼び出し元の`OptimizerForm.tsx`側が既に`flex flex-col gap-6`で間隔を管理しているため不要かつ不整合の原因だった。両方とも`mt-4`を削除し、親のgapのみに間隔を委ねて解決した
- ページ・セクションを組み立てるときは「このブロック群はここでまとめてflex-col + gap-Nにする」と決め、個々のブロックは自分がどこに置かれても外側の余白を意識しなくてよい状態を保つ。既存の間隔を変えたいときも、触るのは親のgap値1箇所で済むようにする
- **例外（対象外）**: アイコンをテキストの1行目のベースラインに視覚的に揃えるための`mt-0.5`のような、**兄弟要素間の間隔ではなく要素内部の微調整**のためのmarginはこの規約の対象外（例: `<AlertTriangle className="h-4 w-4 shrink-0 mt-0.5" />` は許容）
- 判断基準: そのmarginを消したときに「兄弟要素との間隔が詰まって見える」なら間隔管理用（→ 親のgapへ寄せる）。「アイコンや装飾がテキストとズレて見える」なら整列用（→ そのままでよい）

## スペーシングの目安（`gap-*`・`p-*`）

このコードベースで実際に使われている頻度・文脈から見た目安（迷ったときの初期値）。キャノニカルクラスの選び方自体（`h-[30px]`ではなく`h-7.5`等）は`coding-conventions.md`を参照。

| クラス | px | 用途 |
| --- | --- | --- |
| `gap-0.5` / `gap-1` | 2px / 4px | アイコン+ラベルのような1つの塊の中の詰めた間隔、バッジ内部 |
| `gap-1.5` | 6px | インラインの小さなクラスタ（アイコン+短いラベルのボタン等） |
| `gap-2` | 8px | 同じグループ内の要素同士（リストの行同士、ツールバーのボタン同士） |
| `gap-3` | 12px | 1つの小セクション内でまとまった行・ブロック同士（例: タブ行・アクションボタン行・一覧、のような帯同士） |
| `gap-4` | 16px | 1枚のカード/パネル内のサブセクション同士 |
| `gap-6` | 24px | ページ内の独立した大きなブロック同士（ページ直下の`flex flex-col gap-6`等） |
| `gap-8`以上 | 32px+ | 大きな区切りが必要な稀なケースのみ。多用しない |

同じ階層に並ぶ要素は同じgap値で揃える。「タブ行→ボタン行→一覧」のように意味的にひとまとまりの帯を並べる場面で、一部だけ`gap-2`他が`gap-4`のように混在させない。

`space-y-*`/`space-x-*`/`divide-y`もmargin-basedであり、上記の「兄弟間の間隔をmargin側に持たせない」規約と同じ問題（二重の余白）を起こしうる。新規コードでの兄弟間の間隔は`flex flex-col gap-*` / `grid gap-*`で管理し、`space-y-*`系は使わない。

### `p-*`/`px-*`/`py-*`の目安

| クラス | 用途 |
| --- | --- |
| `p-2` | アイコンボタンのヒット領域 |
| `p-3` / `px-3 py-2` | コンパクトな行・小さめのカード内側の余白 |
| `p-4` | カード/パネルの標準的な内側の余白（最も多用） |
| `p-6` | 大きめのカード・モーダル/ドロワーのコンテンツ領域 |
| `px-1.5 py-0.5` / `px-2 py-1.5` | バッジ・チップ・小さなボタンの詰めた余白 |

## 角丸（`rounded-*`）の目安

| クラス | 用途 |
| --- | --- |
| `rounded-full` | アバター、ステータスチップ、丸いアイコンバッジ、ピル型ボタン |
| `rounded-2xl` | 最上位のカード・パネル（例: `OptimizationStepCard`、`OptimizerForm`のルート） |
| `rounded-xl` | 2番目の階層のカード・セクション、モーダル/ドロワーのコンテンツ |
| `rounded-lg` | 通常のボタン・入力・小さめのリスト行・カード内の小ブロック |
| `rounded-md` | タブ/フィルタバー内の個々のボタンのような、密なコントロール内部の要素 |
| `rounded-sm` | ごく小さい要素、密なUI内の細部 |

外側のカードより内側のブロックのほうが角丸が大きくならないようにする（ネストするほど`rounded-*`は同じか小さくする）。

## アイコンサイズの目安（`h-N w-N`）

| クラス | px | 用途 |
| --- | --- | --- |
| `h-3 w-3` | 12px | 最小の装飾的アイコン |
| `h-3.5 w-3.5` | 14px | `text-xs`ラベルに添えるインラインアイコン（最も多用）|
| `h-4 w-4` | 16px | `text-sm`本文・ボタンに添える標準アイコン（最も多用） |
| `h-5 w-5` | 20px | セクション見出し・強調アイコン |
| `h-6 w-6`以上 | 24px+ | 色付き丸バッジの中に入れる機能アイコン等、特別な強調時のみ |

丸バッジ（`h-8 w-8`〜`h-14 w-14`程度の`rounded-full`コンテナ）の中に入れるアイコン自体は上記より一段小さいサイズ（`h-3.5`〜`h-5`程度）を使い、バッジの余白でサイズ感を出す。バッジ/アバターのコンテナ自体のサイズも`h-8 w-8`（標準的なアイコンボタン相当）〜`h-14 w-14`（大きめのアバター等）のキャノニカルクラスに揃える。

## テキストサイズ・フォントウェイトの目安

- 本文・メタ情報の大半は`text-xs`。カード内の主要な行・見出しは`text-sm`。`text-base`以上はページタイトル等ごく一部の見出しにのみ使う（多用しない）
- 強調は`font-bold`を基本とする（このコードベースの標準的な強調ウェイト）。見出し・重要な数値・`uppercase tracking-widest`なラベル等、より強い強調が必要な箇所のみ`font-black`を使う
- `font-medium`/`font-semibold`は新規のアプリ側コードでは基本使わない（shadcn/uiプリミティブ自体が内部で使っているものはそのままでよい）。独自に強調ウェイトを選ぶときは`font-bold`→`font-black`の2段階で足りるかをまず検討する

## 色: `bpim-*`セマンティックトークンを使う

- `src/styles/globals.css`でテーマ（ライト/ダーク等）ごとに定義されたCSS変数がTailwindユーティリティとして公開されている: `bg/text/border-bpim-{bg,surface,surface-2,overlay,primary,primary-dim,border,border-dim,text,muted,subtle,success,danger,warning,info}`。テキスト・背景・ボーダー・状態色（成功/エラー/警告/情報）は必ずこれらのトークンを使い、生のTailwindパレット色（`red-500`・`emerald-400`等）を意味づけ（成功/危険/警告/情報や本文/ボーダー/サーフェス）の代わりに使わない
- 例外: ランキング色分け・チャート系列色・グラフの凡例のような、テーマの意味を持たない一回限りの装飾色は生のTailwindパレット色を使ってよい
- 不透明度は`bpim-*`トークンに`/NN`サフィックスを付けて表現する（独自の`opacity-*`ユーティリティではなく）。目安: `/5〜/20`は薄いtint背景、`/30〜/50`はボーダー・オーバーレイ、`/60〜/80`はスクリム（`bg-bpim-overlay/50`等）

## 選択中/アクティブ状態の表現

- カード・選択肢が「選択中」であることを示す標準パターン: `border-bpim-primary bg-bpim-surface shadow-[0_0_0_3px] shadow-bpim-primary/20`。独自の`ring-*`/アウトラインを都度発明せず、このパターンに揃える

## トランジション（`transition-*`/`duration-*`）

- 色・背景色のみが変化するホバー等は`transition-colors`、幅・transform・opacityも同時に変化する場合は`transition-all`を使う
- durationは`duration-200`をデフォルトとする。shadcn/uiのオーバーレイ系プリミティブ（dialog/sheet/select/popover/dropdown/combobox）は`duration-100`に揃えられているため、それらに合わせて触る場合は`duration-100`のままにする
- プログレスバー・グラフの棒等、データに応じて伸縮するアニメーションのみ`duration-500`以上を使う

## `backdrop-blur-*`

- モーダル/ドロワー/ダイアログの背景スクリムや半透明セクション背景には`backdrop-blur-sm`
- 画面上に固定・追従表示されるヘッダーやチャートのツールチップ等、浮いた要素の背景には`backdrop-blur-md`

## `z-index`（`z-*`）

グローバルなオーバーレイの重なり順は`src/components/ui/`のプリミティブ側で以下の数値スケールとして既に決まっている。新規コードでこのスケールと競合する可能性のある要素（モーダル・ドロワー・ポップオーバー等）を作るときは、このスケールに乗せる。それ以外のローカルなスタッキングコンテキスト調整（`z-0`〜`z-20`程度）はこのスケールと無関係なので自由に使ってよい。

| 値 | 用途 |
| --- | --- |
| `z-1000` | サイドバー/ドロワーのオーバーレイ・基準レイヤー |
| `z-1002` | ドロワーのコンテンツ |
| `z-1003` | ダイアログのオーバーレイ（ドロワーより手前） |
| `z-1005` | ダイアログのコンテンツ |
| `z-1010` | ポップオーバー/セレクト/ドロップダウン/ツールチップ/コンボボックス（ダイアログの中で開いても手前に表示される） |
| `z-1012` | ドロワーの中でさらに開くネストしたドロワー |
